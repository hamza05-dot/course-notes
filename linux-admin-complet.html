Partie 1

🖥️ Gestion des Disques

Cycle de gestion d'un disque :
Partitionnement → Formatage → Montage → (Optionnel) Swap

📌 Tables de Partitionnement

MBR (Master Boot Record)

  • Limité à 4 partitions principales
  • Pour plus : créer une partition étendue contenant des logiques (numérotées à partir de 5)
  • Supporte les disques ≤ 2 To
  • Héritage BIOS

GPT (GUID Partition Table)

  • Standard moderne UEFI
  • Supporte disques > 2 To
  • Jusqu'à 128 partitions
  • Plus robuste et recommandé

🛠️ Commandes de Partitionnement

CommandeUsageType
lsblkLister les disques et partitions (/dev/sdb…)Lecture
fdisk /dev/sdbOutil interactif pour MBRMBR
gdisk /dev/sdcOutil interactif pour GPTGPT
parted /dev/sdbOutil avancé : mklabel gpt, mkpart primary ext4 1MiB 257MiBMBR/GPT
Touches interactives de fdisk
nNouvelle partition
pPartition primaire
ePartition étendue
tChanger le type (82=swap, 8e=LVM)
wÉcrire et quitter
qQuitter sans sauvegarder

📁 Systèmes de Fichiers & Formatage

EXT4

  • Standard Linux généraliste
  • Supporte la réduction du volume
  • mkfs.ext4 /dev/sdb1

XFS

  • Standard RHEL/CentOS, très performant
  • Pas de réduction directe
  • mkfs.xfs /dev/sdb1

📂 Montage & /etc/fstab

# Montage temporaire
mount /dev/sdb1 /mnt

# Trouver l'UUID (recommandé pour fstab)
blkid

# Syntaxe /etc/fstab
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx  /point  ext4  defaults  0  0
💡 Conseil : Toujours utiliser l'UUID dans /etc/fstab plutôt que /dev/sdbX — les noms de périphériques peuvent changer, pas les UUID.

💾 Gestion du Swap

1
Créer la partition swap
fdisk → type 82
2
Formater en swap
mkswap /dev/sdb2
3
Activer le swap
swapon /dev/sdb2
4
Vérifier la mémoire et le swap
free -h
Partie 2

📦 LVM — Logical Volume Management

Hiérarchie LVM :
PV (Physical Volume) → VG (Volume Group) → LV (Logical Volume)

LVM apporte la flexibilité : agrandissement/réduction à chaud, snapshots, pool de stockage partagé.

🧱 Concepts Clés

PV — Physical Volume

Disques ou partitions bruts (type 8e sous fdisk). Brique de base de LVM.

VG — Volume Group

Pool de stockage qui regroupe plusieurs PV. C'est depuis le VG qu'on alloue les LV.

LV — Logical Volume

Partition virtuelle qu'on formate et monte. Équivalent d'une partition classique, mais flexible.

Extent (PE / LE)

Unité minimale d'allocation. PE sur le PV, LE sur le LV. En général 1 PE = 1 LE.

⚙️ Commandes Essentielles

NiveauCréerAfficherÉtendre
PV pvcreate /dev/sdb1 pvs / pvdisplay —
VG vgcreate mon_vg /dev/sdb1 vgs / vgdisplay vgextend mon_vg /dev/sdb2
LV lvcreate -L 2G -n mon_lv mon_vg lvs / lvdisplay lvextend -L +1G -r /dev/mon_vg/mon_lv
✅ L'option -r dans lvextend redimensionne automatiquement le système de fichiers. Sans -r, il faut le faire manuellement.

↕️ Redimensionnement

Extension (EXT4 & XFS)

  • lvextend -L +1G -r /dev/mon_vg/mon_lv (automatique)
  • Ou manuellement :
    XFS → xfs_growfs /point_montage
    EXT4 → resize2fs /dev/...

⚠️ Réduction (EXT4 UNIQUEMENT)

Ordre strict à respecter :

1
Démonter
umount /point
2
Vérifier le FS
e2fsck -f /dev/...
3
Réduire le FS
resize2fs /dev/... 1G
4
Réduire le LV
lvreduce -L 1G /dev/...
5
Remonter
mount /dev/... /point

📸 Snapshots LVM

# Créer un snapshot
lvcreate -s -n mon_snap -L 100M /dev/mon_vg/mon_lv

# Restaurer depuis un snapshot
lvconvert --merge /dev/mon_vg/mon_snap
Partie 3

🔷 Stratis — Stockage Avancé

Stratis combine LVM et XFS pour simplifier la gestion via des volumes à allocation fine (Thin Provisioning). Il abstrait la complexité de LVM en une interface simple.

🏗️ Architecture Stratis

Backstore

  • dm-cache — Cache des données chaudes
  • dm-raid — Redondance RAID
  • dm-integrity — Intégrité des données

Thinpool

  • dm-thin — Provisionnement fin
  • Contient les systèmes de fichiers XFS
  • Allocation à la demande

⚙️ Utilisation de Stratis

1
Installation & démarrage
dnf install stratisd stratis-cli && systemctl enable --now stratisd
2
Préparer les disques (effacer les métadonnées)
wipefs -a /dev/sdb
3
Créer un pool
stratis pool create mon_pool /dev/sdb
4
Ajouter un disque au pool
stratis pool add-data mon_pool /dev/sdc
5
Créer un système de fichiers
stratis fs create mon_pool mon_fs
6
Créer un snapshot
stratis fs snapshot mon_pool mon_fs mon_snap
⚠️ Montage Stratis dans /etc/fstab : Ajouter l'option x-systemd.requires=stratisd.service pour que le montage attende le démarrage du démon Stratis.
Partie 4

🌐 Stockage Distant — NFS, Samba & Autofs

NFS — Linux ↔ Linux

Partage natif Unix, léger et efficace en réseau homogène Linux.

Samba — Linux ↔ Windows

Partage compatible SMB/CIFS. Interopérabilité avec les clients Windows.

📤 NFS — Serveur

# Configurer les exports
# Fichier : /etc/exports
/partage  *(rw,sync,no_root_squash)

# Appliquer les changements
exportfs -ra

# Activer le serveur NFS
systemctl enable --now nfs-server

# Ouvrir le pare-feu
firewall-cmd --add-service={nfs,rpc-bind,mountd} --permanent
firewall-cmd --reload
Options de /etc/exports
rwLecture et écriture
syncÉcriture synchrone (plus sûr)
no_root_squashLe root distant = root local (attention : risque de sécurité)
roLecture seule
# Client NFS : monter un partage
mount -t nfs IP_SERVEUR:/partage /mnt

🪟 Samba — Partage Windows/Linux

# Fichier de configuration : /etc/samba/smb.conf
[public]
   path = /srv/public
   browseable = yes
   writable = yes

[private]
   path = /srv/private
   valid users = hamza
   writable = yes

# Créer un utilisateur Samba
smbpasswd -a utilisateur

# Client : monter un partage Samba (CIFS)
mount -t cifs //IP_SERVEUR/partage /mnt -o user=utilisateur

🔄 Autofs — Montage Automatique à la Demande

Avantage : Autofs monte les ressources uniquement quand on y accède et les démonte après inactivité. Évite de consommer des ressources inutilement.
Type de mappePoint de montageExemple
Directe Point fixe défini dans la mappe /- /etc/auto.direct
Indirecte Sous-dossiers dynamiques créés à la demande /users /etc/auto.users 
# Mappe indirecte avec wildcard (auto.users)
# * = n'importe quel nom d'utilisateur
# & = réutilise le même nom comme dossier distant
*  -rw,sync  serveur:/home/&

Partie 7

⏰ Planification des Tâches — Cron & AT

Cron — Tâches Récurrentes

  • Éditer : crontab -e
  • Lister : crontab -l
  • Supprimer : crontab -r

AT — Tâche Unique

  • Programmer : at 12:00
  • File d'attente : atq
  • Supprimer : atrm ID
  • Voir le contenu : at -c ID

📐 Syntaxe Cron

Format de la ligne crontab
┌───────── Minute        (0–59)
│ ┌─────── Heure         (0–23)
│ │ ┌───── Jour du mois  (1–31)
│ │ │ ┌─── Mois          (1–12)
│ │ │ │ ┌─ Jour semaine  (0–7, 0 et 7 = dimanche)
│ │ │ │ │
* * * * *  /chemin/vers/commande
ExpressionSignification
* * * * *Toutes les minutes
0 2 * * *Chaque jour à 2h00
*/5 9-17 * 7 5Toutes les 5 min, entre 9h et 17h, les vendredis de juillet
0 0 1 * *Le 1er de chaque mois à minuit
30 8 * * 1-5Du lundi au vendredi à 8h30

⏱️ AT — Exemples

at 12:00                 # Aujourd'hui à midi
at now + 5 minutes       # Dans 5 minutes
at teatime               # À 16h00 ("teatime")
at tomorrow + 2 hours    # Demain dans 2h

🔒 Contrôle d'Accès AT

Priorité : Si /etc/at.allow existe, seuls les utilisateurs listés peuvent utiliser AT, même si /etc/at.deny contient d'autres entrées. at.allow est toujours prioritaire.
SituationQui peut utiliser AT ?
Seul at.allow existeUniquement les users listés dans at.allow
Seul at.deny existeTous sauf ceux dans at.deny
Les deux existentUniquement ceux dans at.allow
Aucun fichierSeul root (selon la config)

🐳 Conteneurisation avec Podman

Podman vs Docker : Podman est daemonless (pas de service en fond), supporte le mode rootless (sans root), et est compatible avec les commandes Docker. Il s'intègre nativement avec systemd.

🔄 Cycle de Vie d'un Conteneur

ÉtapeCommandeDescription
Chercherpodman search nginxRechercher une image dans les registries
Téléchargerpodman pull nginxTélécharger l'image localement
Lister imagespodman imagesVoir les images disponibles
Lancerpodman run ...Créer et démarrer un conteneur
Lister conteneurspodman ps -aTous les conteneurs (actifs + arrêtés)
Arrêterpodman stop nomArrêt gracieux
Supprimerpodman rm nomSupprimer un conteneur
Supprimer imagepodman rmi imageLibérer l'espace disque

🚀 Lancer un Conteneur

podman run --name web -d \
       -p 8080:80 \
       -v /data:/var/www/html:Z \
       nginx
Options de podman run
--nameDonner un nom au conteneur
-dMode détaché (arrière-plan)
-p hôte:conteneurRedirection de port
-v /local:/conteneur:ZVolume pour la persistance. :Z = étiquette SELinux
-e VAR=valeurVariable d'environnement
--rmSupprimer le conteneur à l'arrêt

🔧 Conteneur en Service Systemd

Podman peut générer un fichier .service pour transformer un conteneur en service systemd qui démarre automatiquement.
1
Générer le fichier service
podman generate systemd --name mon_cont --files --new
2
Copier dans le dossier systemd utilisateur
cp *.service ~/.config/systemd/user/
3
Activer et démarrer le service
systemctl --user enable --now container-mon_cont.service
4
Activer le Linger (service même sans session)
loginctl enable-linger $USER
⚠️ Linger : Sans loginctl enable-linger, le service conteneur s'arrête dès que l'utilisateur se déconnecte. Le Linger permet au service de tourner même sans session ouverte.
