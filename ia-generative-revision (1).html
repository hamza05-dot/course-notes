PARTIE 1 Fondamentaux de l'IA Générative

🎯 Définition : L'IA générative est une branche de l'IA capable de créer du contenu original (texte, images, code, musique…) en apprenant les modèles sous-jacents des données. Contrairement à l'IA discriminative qui classifie, l'IA générative crée.

🧠 Qu'est-ce qu'un LLM ?

LLM = Large Language Model — modèle d'IA entraîné sur d'énormes corpus de texte, contenant des milliards de paramètres, capable de comprendre et générer du langage humain.

🏋️ Entraînement vs Fine-tuning

🔵 Pré-entraînement

  • Apprentissage non supervisé
  • Énormes corpus de texte (trillions de tokens)
  • Apprend les structures linguistiques générales
  • Coût énorme (millions de dollars)
  • Modèle généraliste

🟢 Fine-tuning

  • Adaptation d'un modèle pré-entraîné
  • Données spécifiques à un domaine
  • Apprentissage supervisé + RLHF
  • Moins coûteux que de partir de zéro
  • Améliore précision dans le domaine cible

📋 Glossaire clé

EmbeddingReprésentation vectorielle numérique d'un texte capturant son sens

RLHFReinforcement Learning from Human Feedback — alignement par retour humain

⚠️ Limites principales des LLMs

  • 1
    Hallucinations — Production de fausses informations plausibles. Le modèle ne "sait" pas ce qu'il ne sait pas.
  • 2
    Connaissances figées — Dépendance aux données d'entraînement, pas de mise à jour en temps réel.
  • 3
    Fenêtre de contexte limitée — Ne peut traiter qu'un certain nombre de tokens à la fois.
  • 4
    Biais — Reproduit les biais présents dans les données d'entraînement.
  • 5
    Coût élevé — En ressources computationnelles pour l'entraînement et l'inférence.

PARTIE 2 Prompt Engineering

🎯 Définition : L'art et la science de formuler des consignes claires, structurées et stratégiques pour obtenir de meilleures réponses d'un LLM. Un bon prompt cadre la tâche, explicite le besoin et réduit les ambiguïtés.

🧩 Les 6 composants d'un bon prompt

  • 1
    La tâche — Ce qu'il faut faire exactement. Ex : "Résume", "Explique", "Compare"…
  • 2
    Le contexte — Pour qui ? Dans quel domaine ? Avec quelles contraintes ?
  • 3
    Le format — Tableau, liste, plan, résumé, code, JSON, fiche…
  • 4
    Le ton — Pédagogique, formel, commercial, technique, simple…
  • 5
    Les critères de qualité — Précision, clarté, concision, exemples concrets…
  • 6
    Les limites — Longueur (ex: "moins de 120 mots"), langue, sources, interdits.

📊 Faible → Moyen → Fort

NiveauExemple de promptProblème / Avantage
❌ Faible "Explique les réseaux de neurones." Trop vague, aucun public cible, aucun format
⚡ Moyen "Explique les réseaux de neurones à des étudiants débutants." Public défini mais pas de format ni de longueur
✅ Fort "Explique les réseaux de neurones à des débutants en 6 points simples, avec une analogie concrète, un exemple en reconnaissance d'images et une erreur fréquente à éviter." Format, public, contenu, exemples → réponse exploitable directement

🛠️ Techniques fondamentales

🎭 Role Prompting

  • Donner un rôle explicite au modèle
  • "Tu es un enseignant universitaire..."
  • "Tu es un expert en cybersécurité..."
  • Change le style et l'angle de réponse

📐 Format de sortie

  • Liste à puces, tableau comparatif
  • Plan en 3 parties, JSON
  • Fiche de révision, e-mail
  • Imposer la longueur et le niveau

🚀 Techniques avancées

TechniqueDescriptionQuand l'utiliser
Zero-shot Demander sans fournir d'exemple Tâches simples, rapides
One-shot Fournir un seul exemple d'entrée/sortie Clarifier le style attendu
Few-shot Fournir plusieurs exemples Réduire l'ambiguïté, style précis
Chain of Thought (CoT) Guider le modèle à raisonner étape par étape Problèmes complexes, calculs, planification
Décomposition Diviser une tâche complexe en sous-tâches Tâches multi-étapes, contrôle fin
Prompt Chaining Sortie d'un prompt = entrée du suivant Workflows complexes, documents longs
Auto-vérification Demander au modèle de relire sa réponse Améliorer fiabilité, détecter erreurs
Génération → Critique Produire puis critiquer/améliorer Contenu de qualité, analyse approfondie
✅ Exemple Few-shot :
Exemple 1 : Entrée: "L'algorithme a optimisé les paramètres du modèle." → Sortie: "Le programme a réglé automatiquement les paramètres."
Exemple 2 : Entrée: "Le système réalise une classification supervisée." → Sortie: "Le système classe des données à partir d'exemples corrigés."
Maintenant, simplifie : "Le modèle produit une représentation vectorielle du document."
✅ Exemple Chain of Thought :
"Calcule la moyenne de 12, 15 et 9 en suivant 3 étapes : 1) additionner les notes, 2) diviser par le nombre de notes, 3) donner la conclusion en une phrase simple."

❌ Erreurs fréquentes à éviter

🚨 Pièges classiques :
• Croire qu'un prompt long est forcément meilleur
• Mélanger plusieurs tâches contradictoires dans une même consigne ("très court mais très complet et très technique et très simple")
• Oublier le niveau du public cible
• Faire confiance sans vérification (hallucinations !)
• Ne jamais itérer — le bon prompt se construit rarement en une seule fois

PARTIE 3 RAG — Retrieval-Augmented Generation

🎯 Définition : RAG = Génération Augmentée par Récupération d'Information.
Idée centrale : 1) Récupérer des documents pertinents → 2) Injecter ce contenu dans le contexte → 3) Générer une réponse fondée sur ces informations.

❓ Pourquoi le RAG ?

⚠️ LLM seul — Problèmes

  • Ne connaît pas vos documents internes
  • Infos récentes absentes (cutoff)
  • Risque d'hallucination élevé
  • Pas d'accès à une base spécifique
  • Réponses génériques

✅ RAG — Solutions

  • Connecte le LLM à vos documents
  • Informations actualisées
  • Réduit les hallucinations
  • Peut citer les sources utilisées
  • Mise à jour sans réentraîner

🔄 Les 2 phases du RAG

📥 Phase 1 : Indexation

  • Charger les documents (PDF, web…)
  • Nettoyer les données
  • Découper en chunks
  • Calculer les embeddings
  • Stocker dans un vector store

💬 Phase 2 : Question-Réponse

  • Calculer l'embedding de la question
  • Chercher les chunks les plus proches
  • Construire un prompt avec contexte
  • Le LLM génère la réponse finale

📐 Notions fondamentales du RAG

NotionDéfinitionÀ retenir
Document Texte source, PDF, page web, rapport Source brute de connaissance
Chunk Morceau plus petit d'un document ~800 caractères avec overlap ~150
Overlap Chevauchement entre 2 chunks consécutifs Évite de couper une idée importante
Embedding Représentation vectorielle numérique du sens d'un texte Textes proches en sens = vecteurs proches
Similarité vectorielle Distance L2, cosine similarity, produit scalaire Permet la recherche sémantique
Vector Store Base de données qui stocke et indexe les embeddings FAISS, ChromaDB, Qdrant…
Retriever Composant qui interroge le vector store pour les top-k chunks Interface de récupération
Reranker Reclasse les documents récupérés pour améliorer la pertinence Optionnel, améliore la précision
PromptTemplate Prompt paramétrable avec variables {context} {question} Standardise et injecte dynamiquement le contexte
TOP_K Nombre de chunks récupérés par le retriever Généralement 3 à 5

🔍 Recherche sémantique vs recherche lexicale

💡 Clé à retenir : Sans embeddings, la recherche ne trouve que les mots exacts.
Avec embeddings : "Comment m'inscrire ?" peut retrouver "Procédure d'inscription administrative et dépôt du dossier." même sans mots communs.
→ La recherche sémantique capte le SENS, pas seulement les mots.

⚖️ RAG vs Fine-tuning

CritèreRAGFine-tuning
Mise à jour✅ Facile, sans réentraîner❌ Nécessite réentraînement
Coût✅ Faible❌ Élevé
Sources citables✅ Oui❌ Non
Précision domaine⚡ Dépend des docs✅ Très élevée
Vitesse réponse⚡ Plus lente (recherche)✅ Plus rapide
Hallucinations✅ Réduites⚡ Toujours possibles

⚠️ Erreurs fréquentes en RAG

🚨 À éviter :
• Chunks trop grands (contexte trop long dans le prompt) ou trop petits (perd le contexte)
• Documents non nettoyés (bruit = mauvais embeddings)
• Embeddings mal adaptés à la langue ou au domaine
• Absence de consigne claire dans le PromptTemplate
• Croire que le retrieval est correct sans l'évaluer

✨ Bonnes pratiques RAG

✅ Pour améliorer la qualité :
• Ajouter des métadonnées (source, page) aux chunks
• Utiliser un reranker pour affiner les résultats
• Faire du hybrid search (lexical + vectoriel)
• Demander au modèle de citer ses sources dans le prompt
• Tester différentes valeurs de chunk_size, overlap, top-k
• Ajouter dans le prompt : "Si l'info n'est pas dans le contexte, dis-le explicitement"

PARTIE 5 LangGraph — Workflows Avancés

🎯 Définition : LangGraph permet de construire des workflows et agents stateful (avec état partagé entre plusieurs étapes), utile quand un pipeline linéaire simple ne suffit plus.

🧩 Notions LangGraph

NotionRôle
StateL'état partagé entre les noeuds (TypedDict)
NodeUne étape de traitement (fonction Python)
EdgeLien entre deux étapes (séquentiel ou conditionnel)
START / ENDDébut et fin du graphe
StateGraphLe graphe complet à compiler
app.compile()Compile le graphe en application exécutable
app.invoke()Exécute le graphe avec un état initial

📊 Pipeline RAG simple (graphe)

START
→
retrieve
→
generate
→
END
📌 Pourquoi LangGraph plutôt qu'un pipeline simple ?
• Ajouter un noeud de reformulation de la question
• Ajouter un noeud de vérification de pertinence
• Ajouter une branche conditionnelle si aucun document n'est trouvé
• Permettre des boucles (relancer la recherche si contexte insuffisant)

🔍 Recherche avec FAISS

import faiss
from sentence_transformers import SentenceTransformer

docs = [
    "Les frais d'inscription sont payables en ligne.",
    "Le dossier doit etre depose avant le 5 septembre.",
]
model = SentenceTransformer("all-MiniLM-L6-v2")
embeddings = model.encode(docs).astype("float32")

index = faiss.IndexFlatL2(embeddings.shape[1])
index.add(embeddings)

query_vec = model.encode(["Comment payer mon inscription ?"]).astype("float32")
distances, indices = index.search(query_vec, k=2)
print([docs[i] for i in indices[0]])

🔗 Mini pipeline RAG LangChain

from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

rag_chain = (
    {
        "context": retriever | format_docs,
        "question": RunnablePassthrough()
    }
    | prompt
    | llm
    | StrOutputParser()
)
answer = rag_chain.invoke("Comment payer les frais ?")

🕸️ LangGraph minimal

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class RAGState(TypedDict):
    question: str
    context: str
    answer: str

def retrieve_node(state: RAGState):
    docs = retriever.invoke(state["question"])
    return {"context": "\n\n".join(doc.page_content for doc in docs)}

def generate_node(state: RAGState):
    prompt_text = prompt.format(context=state["context"], question=state["question"])
    answer = llm.invoke(prompt_text).content
    return {"answer": answer}

graph = StateGraph(RAGState)
graph.add_node("retrieve", retrieve_node)
graph.add_node("generate", generate_node)
graph.add_edge(START, "retrieve")
graph.add_edge("retrieve", "generate")
graph.add_edge("generate", END)

app = graph.compile()
result = app.invoke({"question": "Quelle est la date limite ?"})

PARTIE 7 Révision Examen — QCM & Quiz

📋 Réponses Quiz — Partie 1 (5 pts)

  • Q1
    Entraînement vs Fine-tuning : Entraînement = de zéro sur un large corpus (non supervisé). Fine-tuning = adapter un modèle pré-entraîné à un domaine spécifique avec des données ciblées.
  • Q2
    Pourquoi fine-tuner ? Améliore la pertinence et la précision des réponses dans un domaine donné. Un modèle générique peut être moins précis ou biaisé dans un contexte spécifique.
  • Q3
    Limites LLMs : Hallucinations · Dépendance aux données d'entraînement · Coût élevé · Fenêtre de contexte limitée · Biais des données.
  • Q4
    Pourquoi RAG ? Améliore la précision en récupérant des informations actualisées/externes. Réduit les hallucinations en fournissant des faits vérifiables.
  • Q5
    RAG vs Fine-tuning : RAG = pas de réentraînement, infos actualisées, sources citables. Fine-tuning = précision maximale dans un domaine, mais coûteux et figé.
