🧬 Chapitre 2 — Héritage (extends) 
public class Animal {
    protected String nom;

    public Animal(String nom) { this.nom = nom; }

    public void afficher() { System.out.println(nom); }
}

public class Chien extends Animal {
    private String race;

    public Chien(String nom, String race) {
        super(nom);   // ← OBLIGATOIRE en première ligne si la classe mère n'a pas de constructeur par défaut
        this.race = race;
    }

    @Override
    public void afficher() {
        super.afficher();   // appel méthode parent
        System.out.println("Race: " + race);
    }
}
🚨 Règles Critiques Héritage 1. Java = héritage SIMPLE uniquement (une seule classe mère)
2. super() doit être la PREMIÈRE instruction du constructeur fils
3. Si la classe mère n'a PAS de constructeur par défaut, super(args) est OBLIGATOIRE
4. Un attribut final ne peut pas être modifié après initialisation
5. Une classe final ne peut pas être étendue

// ── CLASSE ABSTRAITE ──
public abstract class Collaborateur implements ICollaborateur {
    private int matricule;
    private String nom;
    private double coutJournalier;

    public Collaborateur(int mat, String nom, double cout) {
        this.matricule = mat;
        this.nom = nom;
        this.coutJournalier = cout;
    }

    // Méthode abstraite = contrat pour les sous-classes
    public abstract double calculCoutProjet(int n);

    // Méthode concrète partagée
    public void afficher() {
        System.out.println(matricule + " " + nom);
    }
}
// ── INTERFACE ──
public interface ICollaborateur {
    // Méthodes : implicitement public abstract
    boolean equals(Object o);
    boolean moinsCher(Collaborateur c, int n);
    // Variables : implicitement public static final
}

// ── SOUS-CLASSE CONCRÈTE ──
public class Consultant extends Collaborateur {
    private double coutForfaitaire;

    public Consultant(int mat, String nom,
                     double cout, double forfait) {
        super(mat, nom, cout); // ← OBLIGATOIRE
        this.coutForfaitaire = forfait;
    }

    @Override
    public double calculCoutProjet(int n) {
        return n * getCoutJournalier() + coutForfaitaire;
    }
}
✅ Astuce examenQuand une classe abstraite implémente une interface, elle peut ne pas implémenter toutes les méthodes — les sous-classes concrètes devront le faire. C'est le pattern le plus utilisé dans les examens.
💥 Chapitre 4 — Exceptions 
// ── HIÉRARCHIE ──
// Throwable
//   ├── Error (StackOverflowError, OutOfMemoryError) → NE PAS CATCHER
//   └── Exception
//         ├── RuntimeException (Unchecked) → optionnel
//         │     ├── NullPointerException
//         │     ├── ArithmeticException
//         │     └── ArrayIndexOutOfBoundsException
//         └── IOException, SQLException (Checked) → OBLIGATOIRE

// ── CRÉER UNE EXCEPTION PERSONNALISÉE ──
public class JoueurException extends Exception {  // Checked
    public JoueurException(String message) {
        super(message);
    }
}

// ── LANCER L'EXCEPTION ──
public void passerNiveau() throws JoueurException {  // déclarer
    if (pointsExperience < 100) {
        throw new JoueurException("Pas assez d'XP!");  // lancer
    }
    niveauActuel++;
    pointsExperience = 0;
}

// ── ATTRAPER L'EXCEPTION ──
try {
    joueur.passerNiveau();
} catch (JoueurException e) {   // plus spécifique en premier
    System.out.println("Erreur: " + e.getMessage());
} catch (Exception e) {          // plus général ensuite
    System.out.println("Autre erreur");
} finally {                        // TOUJOURS exécuté
    System.out.println("Fin");
}
🚨 Règle d'or : Ordre des catch TOUJOURS du plus spécifique au plus général :
❌ MAUVAIS : catch(Exception e) puis catch(IOException e) → ERREUR COMPILATION
✅ BON : catch(IOException e) puis catch(Exception e)
Mot-cléRôleExemple
throwLancer une exceptionthrow new MonException("msg");
throwsDéclarer dans la signaturevoid f() throws IOException {}
tryBloc à surveillertry { ... }
catchAttraper l'exceptioncatch(Exception e) { ... }
finallyToujours exécutéfinally { fermer(); }

🔑 Chapitre 7 — Mots-clés : static, final, this, super

static

  • • Appartient à la CLASSE, pas à l'instance
  • • Partagé par tous les objets
  • • Accessible sans créer d'objet
  • • Méthode static : NE peut PAS utiliser this
  • • Méthode static : NE peut PAS appeler méthodes d'instance

final

  • • Variable final → constante (non modifiable)
  • • Méthode final → ne peut pas être redéfinie
  • • Classe final → ne peut pas être étendue
  • Exemple: String est final !

this

  • • Référence à l'objet courant
  • • Distingue attribut et paramètre
  • • this(args) = appel autre constructeur
  • • Interdit dans méthodes static

super

  • • Référence à la classe parente
  • • super(args) = constructeur parent (1ère ligne!)
  • • super.méthode() = appel méthode parente
  • • Permet d'étendre la méthode parente

🌊 Chapitre 9 — Streams & Lambda (Java 8+) 
import java.util.stream.*;
import java.util.Arrays;
import java.util.List;

List<String> noms = Arrays.asList("Ali", "Bob", "Charlie");

// Opérations INTERMÉDIAIRES (retournent un Stream)
noms.stream()
    .filter(s -> s.length() > 3)    // filtre
    .map(s -> s.toUpperCase())         // transformation
    .sorted()                            // tri
    .distinct();                          // supprime doublons

// Opérations TERMINALES (consomment le Stream)
.forEach(System.out::println)  // affichage
.collect(Collectors.toList())  // → List
.count()                         // nombre d'éléments
.findFirst()                     // premier élément (Optional)
.reduce((a,b) -> a + b)          // réduction

// IntStream.range(2, 6) → 2, 3, 4, 5 (exclusif)
int produit = IntStream.range(2, 6)
    .reduce((a,b) -> a * b)
    .orElse(-1);  // 2*3*4*5 = 120
💡 Différence clé : map() vs filter() filter() = sélectionne des éléments (Predicate → boolean)
map() = transforme des éléments (Function → nouvel objet)

Exercice 1 — Erreurs de compilation classiques 2.5 pts

Trouvez les erreurs dans ce code :

abstract class A { int a; }
class B extends A {
    int b;
    public B(int b) { this.b = b; }  // ← ?
}
class C extends A { final double c = 1; }
abstract class D extends A {
    abstract int calcul(int b) { }   // ← ?
}
class Test {
    public static void main(String[] args) {
        A x = new A();   // ← ?
        B y = new B();   // ← ?
        C z = new C();
        z.c = 3;          // ← ?
    }
}
✅ Solution Commentée
LigneErreurExplication
A x = new A()❌A est abstract → impossible d'instancier

this.b = b dans B❌ manque super()La classe B hérite de A qui n'a pas de constructeur par défaut → super() implicite manquant. MAIS A a un constructeur par défaut (pas de constructeur explicite → Java en crée un). Alors l'erreur principale est sur new B()

Exercice 2 — Exception personnalisée (pattern examen récurrent) 2.5 pts

Créez une exception DateException et modifiez le constructeur de la classe Date pour la lever si le jour (1-30), le mois (1-12) ou l'année est invalide.

✅ Solution Complète
// 1. Classe d'exception personnalisée
public class DateException extends Exception {
    public DateException(String message) {
        super(message);
    }
}

// 2. Classe Date modifiée
class Date {
    int jour, mois, annee;

    Date(int j, int m, int a) throws DateException {  // déclarer
        if (j <= 0 || j > 30)
            throw new DateException("Jour invalide: " + j);
        if (m <= 0 || m > 12)
            throw new DateException("Mois invalide: " + m);
        if (a <= 0)
            throw new DateException("Année invalide: " + a);
        this.jour = j;
        this.mois = m;
        this.annee = a;
    }
}

// 3. Utilisation dans main
public static void main(String[] args) {
    try {
        Date d = new Date(15, 13, 2024);  // mois invalide!
    } catch (DateException e) {
        System.out.println(e.getMessage()); // "Mois invalide: 13"
    }
}

// ── PARTIE 1.2 : Classe abstraite Personnage ──
public abstract class Personnage {
    protected String nom;
    protected int niveauActuel = 1;
    protected int pointsExperience = 0;

    public Personnage(String nom) {
        this.nom = nom;
    }

    public void gagnerExperience(int points) {
        this.pointsExperience += points;
    }

    public void passerNiveau() throws JoueurException {
        if (pointsExperience < 100) {
            throw new JoueurException(
                "Pas assez d'XP pour passer le niveau! XP actuel: " + pointsExperience);
        }
        niveauActuel++;
        pointsExperience = 0;
    }
}

// ── PARTIE 1.3 : Classe Joueur ──
public class Joueur extends Personnage implements IJoueur {
    private String specialite;

    public Joueur(String nom, String specialite) {
        super(nom);
        this.specialite = specialite;
    }

    @Override
    public void jouerTour() {
        System.out.println(nom + " joue son tour!");
    }

    public boolean aMemeSpecialite(Joueur autre) {
        return this.specialite.equals(autre.specialite);
    }

    public void afficherResume() {
        System.out.println("Joueur: " + nom + " | Spécialité: " + specialite
            + " | Niveau: " + niveauActuel + " | XP: " + pointsExperience);
    }
}

// ── PARTIE 3 : JeuSplitFiction ──
import java.util.*;

public class JeuSplitFiction {
    private ArrayList<Joueur> joueurs = new ArrayList<>();
    private ArrayList<Niveau> niveaux = new ArrayList<>();

    public void ajouterJoueur(Joueur j) { joueurs.add(j); }
    public void ajouterNiveau(Niveau n) { niveaux.add(n); }

    public void joueurPasseNiveau(String nomJoueur) {
        for (Joueur j : joueurs) {
            if (j.getNom().equals(nomJoueur)) {
                try {
                    j.passerNiveau();
                    System.out.println(nomJoueur + " passe au niveau suivant!");
                } catch (JoueurException e) {
                    System.out.println("Erreur: " + e.getMessage());
                }
                return;
            }
        }
        System.out.println("Joueur non trouvé: " + nomJoueur);
    }

    public void supprimer(int indice) {
        if (joueurs.isEmpty()) {
            System.out.println("Liste vide");
            return;
        }
        joueurs.remove(indice);
    }

    public boolean trouverJoueurParNom(String nom) {
        for (Joueur j : joueurs)
            if (j.getNom().equals(nom)) return true;
        return false;
    }

    public void trierJoueurs() {
        joueurs.sort((a, b) -> a.getNom().compareTo(b.getNom()));
        joueurs.forEach(Joueur::afficherResume);
    }
}

✅ Réponses types

1. Encapsulation : Mécanisme qui consiste à cacher les attributs d'une classe (les déclarer private) et à contrôler leur accès via des méthodes publiques (getters/setters). Cela protège l'intégrité des données.

2. Checked vs Unchecked :
— Checked : héritent de Exception (sauf RuntimeException). Obligatoire de les gérer (try-catch) ou déclarer (throws). Ex: IOException, SQLException
— Unchecked : héritent de RuntimeException. Gestion optionnelle. Ex: NullPointerException, ArithmeticException

3. Interface vs Classe Abstraite :
— Interface : que des méthodes abstraites (public abstract), attributs public static final, implémenté avec implements, héritage multiple possible
— Classe abstraite : méthodes abstraites ET concrètes, attributs de tout type, étendue avec extends, héritage simple, peut avoir constructeurs

Problème — Gestion d'une Bibliothèque (14 points) 14 pts

Une bibliothèque gère des documents (Livres et Rapports).

Partie 1 (6 pts) — Déclarez une interface IDocument avec :
 • String getInfo() : retourne les infos du document
 • boolean estDisponible() : vérifie si des copies sont disponibles

Partie 2 (5 pts) — Créez une classe abstraite Document implémentant IDocument avec :
 • Attributs privés : code (String), titre (String), nbCopies (int)
 • Constructeur(code, titre, nbCopies)
 • estDisponible() → true si nbCopies > 0
 • abstract String getInfo()
Sous-classe concrète Livre avec numEdition (int), datePublication (String).

Partie 3 (3 pts) — Classe Bibliotheque avec ArrayList<Document>. Méthodes : ajouterDocument, rechercherDocument(String titre), afficherDisponibles().

✅ Solution
// INTERFACE
public interface IDocument {
    String getInfo();
    boolean estDisponible();
}

// CLASSE ABSTRAITE
public abstract class Document implements IDocument {
    private String code, titre;
    private int nbCopies;

    public Document(String code, String titre, int nbCopies) {
        this.code = code; this.titre = titre; this.nbCopies = nbCopies;
    }

    public boolean estDisponible() { return nbCopies > 0; }
    public String getTitre() { return titre; }
    public int getNbCopies() { return nbCopies; }
    public void setNbCopies(int n) { this.nbCopies = n; }
}

// SOUS-CLASSE CONCRÈTE
public class Livre extends Document {
    private int numEdition;
    private String datePublication;

    public Livre(String code, String titre, int nb, int ed, String date) {
        super(code, titre, nb);
        this.numEdition = ed; this.datePublication = date;
    }

    @Override
    public String getInfo() {
        return "Livre: " + getTitre() + " Ed." + numEdition
             + " (" + datePublication + ") - Copies: " + getNbCopies();
    }
}

// CLASSE DE GESTION
public class Bibliotheque {
    private ArrayList<Document> documents = new ArrayList<>();

    public void ajouterDocument(Document d) { documents.add(d); }

    public Document rechercherDocument(String titre) {
        for (Document d : documents)
            if (d.getTitre().equals(titre)) return d;
        return null;
    }

    public void afficherDisponibles() {
        for (Document d : documents)
            if (d.estDisponible()) System.out.println(d.getInfo());
    }
}

⚠️ Top 10 Pièges de l'Examen
01Instancier une classe abstraite
new ClasseAbstraite() → ERREUR. Vérifiez toujours si la classe est abstract avant d'instancier.
02Oublier super() dans le constructeur fils
Si la classe mère a un constructeur avec paramètres, super(args) est OBLIGATOIRE en première ligne du constructeur fils. Sans ça → erreur de compilation.
03Ordre des catch inversé
catch(Exception e) avant catch(IOException e) → ERREUR de compilation "unreachable code". Toujours : sous-classe avant super-classe.
04Confondre throw et throws
throw new Exception() = lancer (dans le corps). throws Exception = déclarer (dans la signature). Les deux souvent requis ensemble.
05Méthode abstraite avec corps { }
abstract void f() { } → ERREUR. Une méthode abstraite ne peut PAS avoir de corps. Il faut : abstract void f();
06== au lieu de .equals() pour les String
== compare les références. "Hello" == new String("Hello") est false. Toujours utiliser .equals() pour comparer le contenu des Strings et objets.
07Modifier un attribut final
final double c = 1; ... z.c = 3; → ERREUR. Final = constante. Vérifiez le mot-clé final dans les attributs.
08Oublier que finally s'exécute toujours
Même avec un return dans catch, finally s'exécute. Peut modifier la valeur retournée (piège de QCM).
09Appeler méthode d'instance dans méthode static
Une méthode static ne peut pas utiliser this ni appeler des méthodes d'instance directement. Erreur commune dans les exercices QCM.
10Une classe abstraite doit contenir des méthodes abstraites
FAUX ! Une classe peut être déclarée abstract sans avoir de méthode abstraite. Elle ne peut simplement pas être instanciée.
⚡ Révision Dernière Minute (30 minutes avant l'examen)

🏗️ Structure d'une classe abstraite

  • abstract class Nom implements Interface
  • Attributs private + getters/setters
  • Constructeur(paramètres)
  • abstract type methodeAbstraite()
  • Méthodes concrètes partagées

💥 Recette exception personnalisée

  • class MonException extends Exception
  • Constructeur avec super(message)
  • Méthode : throws MonException (signature)
  • if(condition) throw new MonException("msg")
  • main : try { } catch(MonException e) { }

📦 Classe de gestion (ServiceInfo style)

  • ArrayList<Type> liste = new ArrayList<>()
  • ajouter : if(!contains) → add
  • retirer : trouver le min, remove(objet)
  • trier : sort avec lambda comparateur
  • Polymorphisme : parcourir avec for-each

🎯 QCM : Réflexes rapides

  • abstract → pas d'instanciation
  • final → pas de modification/héritage/override
  • static → partagé, pas de this
  • protected → visible sous-classes + package
  • throw ≠ throws (lancer ≠ déclarer)
  • finally → TOUJOURS exécuté

🔗 Mots-clés à retenir

  • extends → héritage (classe/interface)
  • implements → interface
  • super() → constructeur parent (1ère ligne)
  • @Override → redéfinition
  • instanceof → vérifier type avant cast
  • this → objet courant

⚖️ Checked vs Unchecked

  • CHECKED : extends Exception → obligatoire
  • IOException, SQLException = checked
  • UNCHECKED : extends RuntimeException → optionnel
  • NullPointerException, ArithmeticException = unchecked
  • Error (StackOverflow) = NE PAS catcher
🏆 Top 20 Faits à Mémoriser
  1. 01Une classe abstraite ne peut pas être instanciée (new impossible). Il faut une sous-classe concrète.
  2. 02super() doit être la PREMIÈRE instruction du constructeur d'une classe fille.
  3. 03Les attributs d'une interface sont implicitement public static final (constantes).
  4. 04Les méthodes d'une interface sont implicitement public abstract.
  5. 05Java permet héritage simple (extends) mais implémentation multiple (implements).
  6. 06throw = lancer l'exception (action). throws = déclarer dans la signature (information).
  7. 07Une exception checked (extends Exception) DOIT être gérée (try-catch) ou déclarée (throws).
  8. 08Le bloc finally s'exécute TOUJOURS, même avec return. Sauf System.exit().
  9. 09L'ordre des catch : du plus spécifique au plus général. Sinon : erreur de compilation.
  10. 10@Override = redéfinition (signature identique, implémentation différente dans sous-classe).
  11. 11Une méthode abstract NE PEUT PAS avoir de corps { }. Juste la déclaration terminée par ;
  12. 12Une méthode static ne peut pas utiliser this ni accéder aux attributs/méthodes d'instance.
  13. 13final variable = constante. final méthode = non redéfinissable. final classe = non extensible.
  14. 14== compare les références mémoire. .equals() compare le contenu. Toujours equals() pour String.
  15. 15contains() sur ArrayList utilise equals() → si vous redéfinissez equals(), contains() en tient compte.
  16. 16Le polymorphisme dynamique : la méthode appelée dépend du TYPE RÉEL (objet), pas du type déclaré (référence).
  17. 17Toujours vérifier avec instanceof avant un downcast pour éviter ClassCastException.
  18. 18IntStream.range(a, b) génère a, a+1, ..., b-1 (borne supérieure EXCLUE).
  19. 19Une classe abstraite n'est pas obligée d'avoir des méthodes abstraites. Elle peut juste empêcher l'instanciation.
  20. 20Une sous-classe NE PEUT PAS ajouter de nouvelles checked exceptions dans une méthode redéfinie.
